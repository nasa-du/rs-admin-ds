## Performance and capacity

`./scripts/perf.sh` (production 2-CPU API limit) and a one-off 4-CPU
experiment:

| Measurement | 2 CPUs | 4 CPUs | Target | Verdict |
|---|---|---|---|---|
| Login, 20 concurrency p95 | **2249.89 ms**, 0 × 503 (other runs: 8–10) | 1422.58 ms, 0 errors | ≤ 1000 ms | **miss** |
| API list, 50 concurrency p95 | **81.12 ms** | 57.55 ms | ≤ 300 ms | pass |
| Refresh, 20 concurrency p95 | **50.03 ms** | 42.85 ms | ≤ 200 ms | pass |
| Refresh grace correctness | 1 new successor/round, reuse delta 0 | same | no false reuse | pass |
| Pool active/max | **3/10 = 0.30** | 3/10 = 0.30 (one sample run hit 9/10) | < 0.8 | pass (production) |

The login target is **risk accepted**: 20 simultaneous Argon2 verifications
need ~4 CPU-seconds, so the 2-CPU API limit has a ~2 s floor and even the
4-vCPU host baseline cannot stay under 1 s with the approved Argon2 cost.
Mitigations (more vCPUs/replicas or an ADR revision of the login SLO; never
lower Argon2 below policy) and the trigger are in
[performance-analysis.md](./performance-analysis.md). Raw reports:
[performance.md](./performance.md), [performance-4cpu.md](./performance-4cpu.md).
